# Domain: hooks
# NORMATIVE when active — a constraint to satisfy, not a claim for you to audit.

## Invariants
- Hooks `SessionStart`, `SessionEnd`, `Stop`, `UserPromptSubmit` receive JSON on stdin: `session_id`, `cwd`, `transcript_path`. `source` (`startup|resume|clear|compact|fork`) is documented for `SessionStart` only; never require it elsewhere. This is the only reliable source of session id and transcript path.
- `SessionStart` does NOT fire for subagents. Use `SubagentStart` / `SubagentStop` (fields: `agent_id`, `agent_type`, parent `session_id`, `transcript_path` of the parent, `agent_transcript_path` of the subagent, `last_assistant_message`).
- `SubagentHandback` is NOT universal (verified TASK-003): the same Explore subagent called it in an interactive session (report in `PreToolUse.tool_input.message`, with `agent_id`/`agent_type` present) and did not call it under `claude -p` (full report in `SubagentStop.last_assistant_message`). Rule: if a `PreToolUse SubagentHandback` was seen for this `agent_id`, take `tool_input.message`; otherwise take `last_assistant_message`. `agent_transcript_path` points at a real file `<parent-session>/subagents/agent-<id>.jsonl` with a `.meta.json` sibling (`spawnDepth`, `toolUseId`).
- `SubagentStop` also fires for Claude Code internal work: in an interactive session EVERY Bash tool call produces a `SubagentStop` with `agent_type: ""` and `last_assistant_message` equal to the command description; no `SubagentStart` precedes them. Primary filter: `agent_type != ""` (empty in all 14 observed noise events). Do not rely on `SubagentStart` having been seen (hooks installed mid-session miss it) and do not treat `background_tasks` as the list of live subagents (the stopping agent is still listed as `running` in its own SubagentStop).
- `transcript_path` is written asynchronously and may lag the current turn; use `last_assistant_message` for the current turn's text.
- `SessionEnd` hooks share a 1.5 s budget (raised only by an explicit per-hook `timeout`, max 60 s): the POST must time out well under that.
- Children of a session (Bash tool, hooks, MCP servers) inherit env `CLAUDECODE=1`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_PID`, `CLAUDE_CODE_CHILD_SESSION=1`. Only `CLAUDECODE` is documented. VERIFIED 2026-09-22 (TASK-003, 9 real SessionStart captures incl. a real interactive one): every claude process, nested or top-level, overwrites `CLAUDE_CODE_SESSION_ID` and `CLAUDE_PID` with its own values, and `CLAUDECODE=1` / `CLAUDE_CODE_CHILD_SESSION=1` are set for true top-level too. In a hook, env session id == stdin session id ALWAYS. None of these variables distinguishes a nested run from a top-level one. `CLAUDE_CODE_SESSION_ATTENDED` (1 interactive / 0 headless) and `CLAUDE_CODE_ENTRYPOINT` (cli / sdk-cli) distinguish interactive from headless only.
- Nesting detection (contract from TASK-003 `scratch/FINDINGS.md`, section Контракт): walk the process tree upward from the hook process; skip the first `claude.exe` ancestor whose pid equals env `CLAUDE_PID` (our own session); the next `claude.exe` ancestor is the parent, resolved through the hub registry `claude_pid -> session_id` (filled from SessionStart, cleared on SessionEnd because Windows reuses pids). Return three states, never `Option`: `TopLevel`, `Nested(parent_session_id)`, `NestedUnknownParent` (ancestor found but not in registry: still no new topic). Guard: if the resolved parent equals our own `session_id` (stale `CLAUDE_PID`), keep walking. The env comparison `env != stdin` stays only as a zero-cost first check; it has never fired. Known hole: a short-lived wrapper process (e.g. `env`) that has exited before the hook runs truncates the chain and the nested run looks top-level; in the real case (a blocking Bash tool call) shells stay alive. The `.cctg/<CLAUDE_PID>` file idea is superseded by the hub registry.
- Hooks must be fast and fire-and-forget: POST to hub with a short timeout, never block Claude Code, never fail the hook when hub is absent (exit 0, log to stderr).
- Hooks are the `cctg hook <event>` subcommand of the same binary; no scripts, no Node.

## Risk lessons
- 2026-09-22 (TASK-003): `.claude/settings.json` hook changes are picked up by already-running interactive sessions without restart; convenient for cctg install, dangerous while probing. Hooks on Windows run through Git Bash, not cmd.exe. Hooks also receive `CLAUDE_PROJECT_DIR` and `CLAUDE_ENV_FILE` (the latter contains the session id in its path).
