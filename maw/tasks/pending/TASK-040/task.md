# TASK-040: client versioning, self-update and in-window restart

Type: feature
Mode: full
Priority: high
Branch: feature/client-self-update
Domains: hub, channel, hooks

## Description
Решение пользователя 2026-09-24: клиент (агент + хуки на машине с claude) сам узнаёт у hub, что устарел, сам обновляется и, если нужно, перезапускается, сохраняя окно терминала (оконные сессии должны остаться в своих окнах, без новых/скрытых консолей). Порядок:
1. Проба: перечитывает ли Claude Code `--settings`/`settings.json` на лету (хуки, statusLine) без перезапуска. Результат определяет, нужен ли перезапуск claude вообще.
2. Версии: `Register` агента и хук-POST несут версию клиента (и хеш бинарника); hub знает свою; расхождение видно в закреплённом статусе (TASK-029) и в логе; новые возможности по-прежнему за capability.
3. Обновление бинарника клиента без перезапуска claude: `cctg agent` становится тонкой стабильной прослойкой, которая держит stdio с Claude Code и запускает рабочий агент дочерним процессом; при новом бинарнике прослойка перезапускает рабочий агент прозрачно для claude (MCP-сессия не рвётся: initialize/tools/list отвечает прослойка или повторяется корректно — спроектировать). Источник бинарника: локальный `~/.cctg/bin` (после `cctg deploy`) или скачивание у hub/из GitHub Releases для удалённых машин (подготовка к TASK-035). Хуки и так запускаются заново на каждое событие.
4. Перезапуск claude в том же окне (решение пользователя 2026-09-24, меняет решение TASK-004 «обёртки cctg run нет»): `claude-cctg` становится подкомандой `cctg run [-- <claude args>]`, которая запускает claude дочерним процессом в той же консоли (общий stdin/stdout, окно то же) и ждёт его. Когда нужен перезапуск (изменились settings или по кнопке из hub), агент пишет файл-заявку (`<state>/restart/<session>.json` с id сессии) и набирает в консоли своего claude `/exit` (механизм WriteConsoleInputW из TASK-029). `cctg run` после выхода claude видит заявку, удаляет её и запускает `claude --resume <id>` с теми же аргументами cctg в том же окне; диалог development channels отвечает сам (он в той же консоли: чтение экрана + ввод). Обычный `/exit` без заявки завершает `cctg run`. Ctrl+C и сигналы идут в claude как раньше. Никаких задач планировщика, скрытых консолей и отдельных вочдогов. Обёртки `claude-cctg` (bash/cmd) становятся тонкими вызовами `cctg run`.

Решение пользователя 2026-09-24 про запуск: обновление и перезапуск никогда не идут сами. Когда hub видит, что клиент сессии устарел (новый бинарник на машине или новая версия у hub), в тему уходит одно сообщение-предупреждение, и в закреплённом статусе (TASK-029) появляется отметка; и в сообщении, и в закрепе есть кнопка «Обновить». Только нажатие allowlisted-пользователя запускает машинерию: подхват бинарника рабочим агентом, а если нужен перезапуск claude — заявка и `/exit` с перезапуском через `cctg run` в том же окне. Если идёт ход, кнопка предупреждает и ждёт конца хода (или предлагает прервать). Предупреждение одно на версию, без повторов.

Принцип пользователя 2026-09-24: `cctg run` и supervisor (TASK-026) должны быть максимально тупыми: они не обновляются без ручного перезапуска, поэтому в них только запуск дочернего процесса, ожидание, перезапуск по файлу-заявке и ответ на диалог каналов. Никакой логики версий, сети, Telegram или парсинга протокола; всё умное живёт в hub и рабочем агенте, которые обновляются сами. Заодно пересмотреть supervisor: вынести из него всё, что может жить в hub/deploy, если это упростит его без потери отката.

## Acceptance criteria
- [ ] `cctg run` и supervisor не содержат логики версий, сети и протокола; их код помещается на один экран каждый (оценка ревью)
- [ ] ничего не обновляется и не перезапускается без нажатия «Обновить»; одно предупреждение на версию, отметка в закрепе, кнопка в обоих местах
- [ ] проба settings reload записана, дизайн от неё зависит
- [ ] устаревший клиент виден в статусе; hub и агенты разных версий работают (capabilities, без VERSION bump)
- [ ] новый бинарник подхватывается рабочим агентом без перезапуска claude, сообщения в процессе не теряются
- [ ] перезапуск в том же окне сохраняет окно и контекст сессии (--resume), диалог каналов отвечен; без шелла — сообщение, а не новое окно
- [ ] никаких новых видимых окон, никаких задач планировщика
- [ ] Existing tests pass
