# TASK-048: coalesce a burst of topic messages into one inbound

Type: bugfix
Mode: small-fix
Priority: high
Branch: fix/coalesce-inbound
Domains: hub, channel

## Description
Найдено пользователем 2026-09-25: пересылка из Telegram (несколько пересланных сообщений плюс своя пометка) приходит пачкой отдельных сообщений за доли секунды. hub отдаёт их в сессию по одному: первое начинает ход, остальные Claude Code держит в очереди до конца хода, и модель видит пересланное без пометки (или наоборот) только ходом позже.

hub склеивает пачку: после входящего сообщения в тему живой сессии ждёт окно тишины (около 1 с, продлевается каждым новым сообщением, но не дольше 3 с от первого) и отправляет всё накопленное одним inbound-сообщением канала: части в исходном порядке, пересланные с их пометкой «переслано от …» и цитаты как сейчас (TASK-030), разделитель между частями. 👀 ставится на каждое исходное сообщение. Файлы (TASK-032) и команды `!`/`/` (TASK-043) в склейку не входят и не задерживаются; они закрывают накопленную пачку (сначала уходит пачка, потом файл или команда), порядок сохраняется. Мёртвый слот (буфер TASK-017) работает как раньше. Логи без текста.

## Acceptance criteria
- [ ] три пересланных и одна пометка за 300 мс приходят в сессию одним сообщением в исходном порядке, 👀 на всех четырёх (тест с фейковым линком)
- [ ] одиночное сообщение уходит через окно тишины, не позже 3 с при непрерывном потоке
- [ ] файл или команда посреди пачки не теряют порядок
- [ ] Existing tests pass
