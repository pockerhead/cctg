## 2. Исследование

- kubeadm join ([Bootstrap tokens](https://kubernetes.io/docs/reference/access-authn-authz/bootstrap-tokens/), [kubeadm join](https://kubernetes.io/docs/reference/setup-tools/kubeadm/kubeadm-join/)): ровно наша схема. Токен `[a-z0-9]{6}.[a-z0-9]{16}`, первая часть публичный id для поиска, вторая секрет; срок `expiration`, просроченные отвергаются и чистятся; отзыв = удаление; первое подключение нового узла идёт с `--discovery-token-ca-cert-hash sha256:...`, то есть с pin'ом сервера до всякого секрета. Отсюда публичный id в секрете устройства и обмен кода только по TLS с pin.
- OWASP [Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html): одноразовые коды из CSPRNG, одно использование, короткий срок, на сервере хранить хеш, не сам код. Отсюда `join/<sha256(code)>.json` с одним сроком внутри и снятие кода первым же использованием.
- NIST SP 800-63B ([5.1.2 look-up secrets](https://pages.nist.gov/800-63-3/sp800-63b.html)): не меньше 64 бит, либо 20 бит при жёстком ограничении попыток. У нас 80 бит без отдельного счётчика неудач: при лимитах TASK-035 (64 запроса хуков, 250 мс на отказ) за 10 минут жизни кода выходит порядка 10^5 попыток против 2^80. Отдельный глобальный лимитер попыток не нужен и был бы вреден: любой снаружи мог бы им заблокировать регистрацию.
- Хранение секретов устройств: для высокоэнтропийных случайных токенов достаточно sha256 и сравнения за постоянное время; bcrypt/Argon2 нужны для паролей с малой энтропией ([OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html); так делают GitHub и Stripe для API-ключей, [apikeys.guide](https://apikeys.guide/docs/security/hashing-and-storage)). Секрет 256 бит, хеш sha256 из уже подключённого `aws-lc-rs`.
- Формат кода: [Crockford base32](https://www.crockford.com/base32.html) — без `I L O U`, при вводе `O→0`, `I/L→1`, регистр не важен. 16 знаков = 80 бит, группы по 4 через дефис, как ключ продукта: читается с телефона и набирается руками.
- `curl` умеет pin только открытого ключа (`--pinnedpubkey sha256//base64` по SPKI), а pin cctg — sha256 всего сертификата (`tls.rs:47-90`). Поэтому обмен делает сам бинарник (`cctg join`), а не curl в `install.sh`.

## 3. Подход

1. **Секрет устройства = новое значение `CCTG_HUB_SECRET`.** Формат `cctgd_<id>_<64 hex>` (79 видимых ASCII, проходит `Secret::parse`), `<id>` 8 hex публичный. Агент и хук шлют его ровно туда же, что и общий секрет: ни `agent.rs`, ни `hook.rs`, ни протокол линка не меняются, `wire::VERSION` тот же, старые клиенты с секретом устройства работают без обновления. Hub ищет устройство по id и сравнивает sha256 всего секрета с сохранённым через `subtle` (`Devices::check`). Отклонено: отдельное поле в `hello`/заголовок с id (правка агента и хука, capability-флаг без выгоды).
2. **`hub/devices.rs` (новый, чистая логика + файлы).** `Devices` — дешёвый клон (`Arc`), одна книга на оба слушателя и `/devices`:
   - `open(state_dir, shared: Option<Secret>)`: `devices.json` `{version:1, devices:[{id,name,joined,hash}]}`; нет файла — пусто; битый, чужая версия, дубли id или не-hex хеш — hub не стартует (как с `registry.json`: пустой список молча выгнал бы все устройства).
   - `check(bytes) -> Option<Who>` (`Who::Shared | Who::Device(id)`), по пути помнит время последнего входа (только в памяти).
   - `join(code, name)`: нормализует код, тратит его (`take_code`), `enroll`: 32 бита id (без повторов), 256 бит секрета из `aws_lc_rs::rand::fill`, sha256, запись temp + fsync + rename с правами 600 на Unix; при ошибке записи устройство не добавляется. Не больше `MAX_DEVICES = 32` (иначе `JoinError::Full`); 32 выбрано, чтобы список со всеми кнопками гарантированно влезал в одно сообщение (тест с худшим случаем).
   - `revoke(id)`: сразу из памяти, потом на диск (если диск не дал записать — отзыв действует до перезапуска, об этом warning и строка в Telegram), `watch::Sender<u64>` оповещает все линки.
   - `subscribe()`, `is_active(who)`, `list()` (устройства и `SharedState::Off | On(last_seen)`), `name(id)`.
   - Коды: `mint_code(state_dir, now)` пишет `join/<sha256(normalized)>.json` с `{"expires": unix}` (temp + rename, чистит просроченные и `.tmp` старше 60 с, не больше `MAX_CODES = 32` живых); `take_code` читает срок, удаляет файл (из двух гонящихся выигрывает один `remove_file`) и проверяет срок. Код в каталоге состояния не лежит, только его хеш. Для книги без каталога (`From<Secret>`, тесты) `join` всегда `Refused`.
   Отклонено: коды в памяти hub (минтит другой процесс — `docker compose exec`), админ-эндпоинт на hub для минта (новая аутентифицированная поверхность).
3. **Ingress.** `serve_agents`, `serve_agents_with`, `serve_hooks`, `serve_hooks_and_permissions`, `serve_hooks_and_asks` принимают `auth: impl Into<Devices>` вместо `Secret`; `impl From<Secret> for Devices` сохраняет все 67 вызовов в тестах без правок. Агент: подписка на `watch` до проверки `hello` (отзыв между проверкой и регистрацией не теряется), в цикле `select!` новая ветка `revoked(...)` закрывает линк (`AgentEvent::Disconnected`, как обрыв). Хук: подписка до `read_request`, каждый запрос проверяется заново (отозванный получает 401 с первого же следующего запроса), ждущие `PermissionRequest`/`AskUserQuestion` отозванного устройства обрываются без ответа (`wait_for` получил четвёртую ветку). Новый маршрут `POST /v1/join` (`Route::Join`): единственный без `Authorization` (заголовок, если есть, игнорируется), тело не больше `MAX_JOIN_BODY = 1024` (читается до всякой аутентификации), `join_request` зовёт `Devices::join` в `spawn_blocking`; успех — 200 с `JoinAnswer{device_id, name, secret}`, любой плохой код — одинаковый 403 после `AUTH_FAIL_DELAY` и `pre_auth!` warning без кода, `Full`/ошибка диска — 503. Места, дедлайн 2 с и лимиты на IP те же, что у хуков. `Status::Forbidden` (403) добавлен.
4. **Hub.** `config.rs`: `SHARED_VAR = "CCTG_SHARED_SECRET"` (`on` по умолчанию | `off`, иначе ошибка без эха значения), `Config.shared_secret`, `config::state_dir(env_file)` (только `CCTG_STATE_DIR` для `cctg hub code`). `hub/mod.rs::run`: секрет обязателен только при `on`; при `off` hub стартует и без него (info-строка); `Devices::open` рядом с реестром; тот же `devices` в оба слушателя и в новый воркер `/devices`. `hub::mint_code(env_file)` для CLI.
5. **`/devices` (`hub/roster.rs`, новый воркер).** `route_inbound` получил канал `roster`: `/devices` (и `/devices@бот`) только в General уходит воркеру; в теме это по-прежнему текст сессии (правило TASK-021). Кнопки `dev:r:<id>` / `dev:y:<id>` / `dev:n` ловятся до актора слотов, так что `slots.rs` не тронут. Сообщение: устройства (имя, id, дата, «на связи N мин назад» или «с запуска hub не появлялось»), состояние общего секрета с последним входом, как добавить устройство. «Отозвать X» правит то же сообщение в подтверждение «Да, отозвать / Отмена»; «Да» отзывает и возвращает список с ««X» отозвано (Имя нажавшего).». Повторное «Да» — «Этого устройства уже нет.». Только plain text (имя устройства присылает устройство, HTML не используется). В логе только id.
6. **Клиент `cctg join [КОД]`** (`join.rs`, новый; код также из `CCTG_JOIN_CODE`): адрес хуков и pin из `DeviceConfig` (TLS с pin или loopback), `POST /v1/join` с `{v, code, name: DeviceConfig.host}` за 10 с, разбор статуса строго `HTTP/1.1 NNN`. Успех: строка `CCTG_HUB_SECRET='...'` заменяет все прежние (`export`, пробелы) в `~/.cctg/device.env`, остальные строки остаются, temp + fsync + rename, 600 на Unix. Печатает имя и id, не секрет и не код; если старый секрет был секретом устройства — напоминает отозвать его; если `CCTG_HUB_SECRET` задан в окружении — предупреждает, что он перекрывает файл. Ошибки: 403 «wrong, already used or expired», 404 «hub older than join codes», 503, нет pin для удалённого hub — без обращения к сети. Выход 0/1, 2 без кода.
7. **`cctg hub code`** (`main.rs`: `Hub { env_file (global), stop_on_stdin, command: Option<HubCommand> }`, `HubCommand::Code`): печатает только код. В Docker `docker compose exec hub cctg hub code` (uid 10001, `CCTG_STATE_DIR=/data` из образа), локально `cctg hub --env-file <тот же> code` из папки hub. `cctg supervise` по-прежнему передаёт `hub --env-file X [--stop-on-stdin]`.
8. **`install.sh`.** `--join КОД` / `CCTG_JOIN_CODE`: секрет не спрашивается и не пишется, после `write_device_env` (адрес и pin уже в файле) `join_hub` запускает `"$exe" join` с кодом в окружении; отказ — `die`, `device.env` не меняется (старый секрет, если был, остаётся). Без кода и секрета в терминале сначала спрашивается код, пустой ответ — прежний скрытый ввод общего секрета; без терминала сообщение называет `--join`. `check_code` пускает только буквы, цифры, дефис и пробел. `--hub`: общий секрет по-прежнему создаётся в `hub.env` (hub с `on` без него не стартует), но больше не печатается; после `wait_hub` скрипт берёт код `docker compose exec -T hub cctg hub code` и печатает строку `... | sh -s -- <адрес> --pin <pin> --join XXXX-XXXX-XXXX-XXXX` и как получить код для следующей машины. `--uninstall` убирает строку секрета устройства как прежде (ключ тот же, `MANAGED`).
9. **`cctg doctor`**: «secret: set, this device's own (device <id>)» или «…the hub's shared secret»; на 401 подсказка про отзыв и `cctg join`.
10. **Миграция** (описана в `docs/remote-hub.md` «Устройства и коды / Миграция»): hub новой версии принимает общий секрет, пока `CCTG_SHARED_SECRET` не `off`; машины по одной переходят `cctg join КОД` (или повтор `install.sh ... --join КОД`); `/devices` показывает, когда с общим секретом входили в последний раз; потом `off` в `hub.env` и перезапуск. Откат — `on`.

## 6. Риски

- **Отзыв не гасит сессии в темах.** Hub не знает, с какого устройства пришла сессия (реестр по `host`), поэтому после отзыва её `SessionEnd` отвергается 401 и слот остаётся «живой без агента» до обычной уборки. Для личного форума терпимо; привязка сессий к устройству — отдельная задача (вопрос 4).
- **Отозванный агент стучится дальше.** Агент после обрыва переподключается с паузой до 30 с и получает `Rejected(Auth)`: на hub это 250 мс места до секрета и один warning в минуту на IP. Остановить агента можно только `/exit` на той машине.
- **Запущенные сессии держат старый секрет.** Агент читает `device.env` только при старте: после `cctg join` старые сессии ходят с общим секретом; если сразу поставить `off`, они потеряют hub до перезапуска. В документации это шаг миграции; `/devices` показывает последний вход с общим секретом.
- **Битый `devices.json` останавливает hub** (как `registry.json`). Сознательно: пустая книга молча выключила бы все устройства. Сообщение называет файл и не цитирует содержимое.
- **Отзыв, не записанный на диск,** действует до перезапуска; hub пишет warning, в Telegram строка «отзовите ещё раз». Редко (диск полон), но честно.
- **Имя устройства от самого устройства.** Чистится (`clean_name`), идёт только plain text; в логи не попадает. Два устройства с одним именем различаются по id.
- **Коды в каталоге состояния от другого процесса.** `cctg hub code` должен видеть тот же `CCTG_STATE_DIR`: в Docker это `/data` из образа, для локального hub — тот же `--env-file` и та же папка (иначе `.cctg` относительный). Ошибка тут выглядит как «код отвергнут»; в документации сказано явно.
- **Часы.** Срок кода по `SystemTime` (unix-секунды), одна машина — минт и проверка в одном контейнере/хосте, расхождения нет.
- **Windows и `remove_file` открытого файла.** std открывает файлы с `FILE_SHARE_DELETE`, `take_code` читает и закрывает файл до удаления; гонка двух обменов даёт одного победителя (`NotFound` у второго).
- **Общие тестовые бинари.** Параллельный прогон TASK-053 в том же `target` уже дважды мешал сборке эталона (блокировка `cctg.exe`, `LNK1104`) и один раз подсунул старый бинарь. `touch lib.rs` и проверка имён тестов в выводе обязательны.

## 7. Открытые вопросы

1. **Свежий `install.sh --hub`: включать общий секрет или нет?** Эталон оставляет как было (секрет создаётся, `on`), чтобы поведение hub не зависело от способа установки. Можно писать `CCTG_SHARED_SECRET=off` только при первой установке, когда старых устройств нет. По умолчанию: оставить `on`.
2. **Подтверждение отзыва.** Эталон спрашивает «Да, отозвать / Отмена» (ошибочный тап на телефоне стоит повторной установки на машине). Если нужна одна кнопка — `Press::Ask` сразу отзывает, тест `the_list_asks_before_it_revokes…` меняется.
3. **Повторный `cctg join` на той же машине** создаёт новое устройство, старое остаётся до отзыва (`cctg join` напоминает его id). Можно отзывать старое автоматически, если в `device.env` был секрет устройства: `join` послал бы его в `Authorization`. По умолчанию: не делать (скрытый отзыв удивляет).
4. **Привязка секрета к имени машины.** Секрет устройства сейчас регистрирует сессии под любым `host`. Можно запретить устройству чужие `host` и помечать его сессии для отзыва. Вне задачи, кандидат в отдельную.
5. **Срок кода.** Фиксированные 10 минут. Для `install.sh --hub` на сервере без доступа к машинам в ближайшие минуты может пригодиться `cctg hub code --minutes N`. По умолчанию: нет.
6. **Для TASK-046 (`/join` в General).** Минт уже есть (`devices::mint_code(state_dir, now)`), но hub не знает публичного адреса и портов для строки: они в `.env` compose (`CCTG_PUBLIC_HOST`) и `compose.yml`, не в `hub.env`. TASK-046 должна добавить их в окружение hub (например, `install.sh --hub` пишет `CCTG_PUBLIC_HOST`/порты в `hub.env`) и pin (hub его знает из сертификата).
