## Description
QA-гейт для шага 4. Сценарий: две одновременные top-level сессии в папке A, одна top-level в папке B, один вложенный `claude -p` внутри одной из сессий A, плюс пятый top-level в папке A, стартующий при выключенном hub и после того, как первая сессия A завершилась. Ожидаемые темы: **три** — `[host] A`, `[host] A #2`, `[host] B`. Вложенный запуск темы не получает. Пятая сессия переиспользует освободившийся слот `[host] A` и добавляет разделитель, новой темы не создаёт. Проверить роутинг, восстановление, приоритеты, счётчики сообщений и итоговый реестр.

Дополнение оркестратора (2026-09-24, после premise challenge): сейчас hub вообще не узнаёт сессию, чей `SessionStart` не дошёл (хук шлёт событие один раз, агент неизвестной сессии ждёт в `pending` навсегда). Пятая сессия сценария без этого невидима. В рамках этой задачи сначала закрыть пробел: хук, не доставивший событие, сохраняет его в спул на диске (`<CCTG_STATE_DIR|~/.cctg>/spool/`, без секретов и текста промптов, с ограничением размера и возраста), а любой следующий хук той же сессии (или агент при регистрации) сначала досылает спул по порядку; hub принимает поздний `SessionStart` как обычный. Затем soak-сценарий как описано.
