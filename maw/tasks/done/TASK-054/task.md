# TASK-054: debounce outbound bursts, stop hitting flood control

Type: feature
Mode: small-fix
Priority: high
Branch: feature/outbound-debounce
Domains: hub

## Description
Запрос пользователя 2026-09-26: при активной работе (несколько сессий, субагенты) hub трижды за три минуты получил 429 (`telegram flood control, outbound queue paused` на 18 с, 28 с, 12 с, лог сервера 12:30-12:33Z). Пауза общая на всю группу, поэтому ответы во всех темах стоят до минуты. Пользователь: «надо дебаунс делать и склеивать сообщения по несколько, если идут пачками».

Сейчас (`crates/cctg/src/hub/scheduler.rs`):
- сообщения (`Message` lane) метрятся bucket'ом 5 шт. + 1 раз в 4 с, мин. зазор 1 с;
- строки стрима склеиваются, только когда очередь длиннее, чем токенов в bucket (`merge_lines`), то есть пока бюджет есть, каждая строка инструмента уходит отдельным сообщением;
- `editMessageText`, `setMessageReaction` (👀/✍, 💭), `answerCallbackQuery`, `editForumTopic`, `pinChatMessage`, `deleteMessage` не метрятся вовсе, только сериализуются. Закреплённый статус (TASK-029) и реакции правятся часто, это вероятный главный источник 429.

Сделать:
1. Дебаунс строк стрима: строка `merge` темы ждёт короткое окно тишины (порядка 1.5 с, не дольше ~4 с от первой строки), и всё, что пришло в это окно для той же темы, уходит одним сообщением (в пределах 4096 и правил `merge_lines`: громкие и тихие не смешиваются, порядок темы сохраняется, permission-промпт не задерживается дебаунсом).
2. Бюджет для правок: edit/reaction/topic-операции тоже расходуют общий бюджет группы (свой bucket или общий с весом), чтобы сумма запросов в группу держалась ниже лимита Telegram. Правки одного сообщения и дальше коалесцируются; статус темы не правится чаще, чем раз в несколько секунд.
3. Не ломать: порядок в теме, permission первым, fallback HTML -> plain, break_stream, поведение при 429 (пауза и повтор).

Числа (окна, ёмкости) подобрать и обосновать в коде константами; Telegram документирует ~20 сообщений в минуту на группу, для правок публичного лимита нет.

## Acceptance criteria
- [ ] Пачка строк стрима одной темы, пришедшая за окно дебаунса, уходит одним сообщением даже при полном бюджете (тест scheduler с фейковым транспортом и paused time)
- [ ] Одиночная строка уходит не позже окна дебаунса; permission-промпт уходит без задержки дебаунса
- [ ] Поток правок (статус, реакции) при нагрузке ограничен бюджетом: за минуту запросов в группу не больше заданного лимита (тест)
- [ ] Все существующие тесты scheduler и e2e проходят
