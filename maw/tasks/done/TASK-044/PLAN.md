## 1. Understanding (что есть сейчас, `main`)

- `crates/cctg/src/keys.rs`: всё управление консолью только Windows. `SUPPORTED = cfg!(windows)` (стр. 28); `press(claude_pid, key)` (37-103) делает `AttachConsole` + `WriteConsoleInputW`; `type_and_watch` (321-372) под `#[cfg(windows)]`: attach, проверка `agents_block`, набор, `ECHO_WAIT`, `input_box`/`box_shows`, Enter или стирание Backspace-ами, потом `close_panel` (405-420) или `cancel_exit_dialog` (427-448); `agents_on_screen` (376-395); `write_text`/`visible_lines` (461-585) читают/пишут присоединённую консоль. На не-Windows всё это заглушки `false`/`None`. Парсеры экрана (`input_box`, `box_shows`, `panel`, `exit_dialog`, `agents_block`, `typable`) платформенно-нейтральны и покрыты тестами.
- `crates/cctg/src/run.rs`: `cctg run` (TASK-040). `run` (36-49) вешает слушатель Ctrl+C и уходит в `run_claude` (51-89): `Command::new(claude)` в той же консоли, `CCTG_RUN`/`CCTG_RUN_ARGS`, поток `answer_channels_dialog` (115-136), который читает `keys::visible_lines()` и жмёт `keys::write_text("\r")`. На Linux/macOS `visible_lines()` = `None`, поток сразу выходит: диалог development channels не отвечается, перезапуск по заявке работает только до диалога (его жмёт человек).
- `crates/cctg/src/agent.rs` 486-514: `claude_pid` из `proctree::current_lineage`, `console = claude_pid.filter(|_| keys::SUPPORTED)`, `Worker::from_env(.., console.is_some())`, затем проверка `update::launched_by` (только `cctg run`, запустивший этого claude, может его перезапускать). `Register.console_keys/console_commands = console.is_some()` (546-547). `spawn_console` (1489-1540) исполняет `ConsoleKey`/`ConsoleCommand` через замыкания `Console { press, type_line }`.
- `crates/cctg/src/update.rs`: `Worker.keys: bool` (82), `restartable` (127-130), `agents_on_screen` (159-162) и `restart` (166-189) зовут `keys::*` по `claude_pid`; `launched_by` (206-218) идёт по цепочке предков claude до `cctg run`, останавливаясь на `claude`/`node`.
- `crates/cctg/src/proctree.rs`: цепочка предков и список живых pid есть на Windows (ToolHelp) и Linux (`/proc`), на macOS `None` (199-255): нет `claude_pid` у агента (нет перепривязки после `/clear`), нет родителя у вложенного `claude -p` (своя тема), нет уборки сессий по живым pid (TASK-039), `shim::remove_dead_links` на macOS ничего не удаляет.
- `crates/cctg/src/hub/console.rs` 36-37: `NO_CONSOLE_NOTICE` говорит «нужен свежий cctg на Windows». Hub сам ничего не знает про ОС: кнопки ⏹ и набор команд зависят только от `Register.console_keys/console_commands` (`hub/slots.rs` 1102-1103), протокол менять не нужно.
- Обёртка `install.sh` 572-576: `exec cctg run -- --mcp-config ... --dangerously-load-development-channels server:cctg --settings ... "$@"`; на Unix её менять не нужно.
- Тесты: `tests/run_e2e.rs` (stdin/stdout null, консоли нет) проверяет перезапуск без экрана; `tests/reap_e2e.rs` под `cfg(any(windows, linux))`; CI (`.github/workflows/ci.yml`) гоняет fmt, clippy `-D warnings` и все тесты на ubuntu, windows, macos.

## 2. Approach

Выбран вариант (б): `cctg run` на Unix сам держит псевдотерминал для claude. tmux-путь (а) не добавляется: пользователи работают в обычных терминалах; `claude-cctg` внутри tmux и так работает через pty `cctg run`; claude, запущенный без `cctg run`, всё равно нельзя перезапустить. Решение в `log.jsonl` (decision).

Как это устроено (эталон):

1. `cctg run` на Unix при stdin и stdout-терминалах (`isatty(0) && isatty(1)`) переводит терминал пользователя в raw-режим (`cfmakeraw`, исходный `termios` сохраняется) и на каждый запуск claude открывает НОВЫЙ pty (`openpty` с режимами и размером терминала пользователя, как `script`): XNU отзывает управляющий терминал при выходе лидера сессии, поэтому один pty на все перезапуски на macOS не работает (dead_end в логе). Оба конца `FD_CLOEXEC`. claude стартует с `setsid()` + `ioctl(0, TIOCSCTTY)` в `pre_exec`, slave как stdin/stdout/stderr; копия slave в `cctg run` закрывается сразу после `spawn`.
2. Реле: поток stdin -> текущий master (один `Mutex<Option<File>>`, в него же пишут агент и Enter диалога, запись целиком под замком, поэтому байты разных источников не перемешиваются внутри одного `write`); поток на каждый pty master -> stdout пользователя + `vt100::Parser` (копия экрана, scrollback 0). Паника эмулятора ловится `catch_unwind`: копия пропадает (агент теряет консоль), реле продолжается.
3. Сигналы (tokio `signal::unix`): SIGWINCH -> `TIOCGWINSZ` терминала пользователя -> `TIOCSWINSZ` master (ядро шлёт SIGWINCH claude) + `Screen::resize`; SIGTERM и SIGHUP -> SIGHUP группе claude, флаг «не перезапускать»; слушатель Ctrl+C остаётся. Ctrl+C, Esc, Ctrl+Z идут байтами (raw-режим). Ожидание через `waitpid(WUNTRACED)`: claude остановил себя (Claude Code на Ctrl+Z шлёт себе SIGSTOP, anthropics/claude-code#4035) -> вернуть режим терминала, остановить себя SIGSTOP (SIGTSTP ядро выбросит: группа осиротевшая), после `fg` снова raw, размер, SIGCONT группе claude. Код выхода: `WEXITSTATUS`, по сигналу `128 + sig`. На выходе `cctg run` 100 мс на последний вывод claude, восстановление режима, удаление сокета.
4. Сокет `<state>/run/<pid cctg run>.sock` (`term::socket_path`), папка 0700, сокет 0600 (на BSD права самого сокета не проверяются, защищает папка). Один запрос на соединение, одна JSON-строка: `"screen"` -> массив строк экрана (или `null`), `{"keys":"<text>"}` -> `true|false`. Запрос до 4 КиБ, таймауты 2 с на обе стороны. Формат заморожен: `cctg run` не обновляется, агент обновляется (тест `the_ask_format_is_frozen`). Никакой логики в `cctg run`: он не знает, что на экране; принцип TASK-040 соблюдён.
5. Агент: `keys::Target { Console(pid), Run(socket) }` без cfg на вариантах; вся логика набора (`watch`, `close_panel`, `cancel_exit_dialog`) идёт по трейту `Terminal { lines, write }`, реализованному Windows-консолью (`Attached`: attach + `FreeConsole` в Drop, тот же мьютекс) и `Run` (запросы в сокет; `\u{8}` -> DEL `0x7f`, как шлёт терминал; текст уходит первым символом, пауза 50 мс, остаток, чтобы ведущий `!`/`/` дошёл до Claude Code отдельной клавишей). Windows-поведение не меняется: те же вызовы Win32 в том же порядке, те же тайминги (`WAITS`).
6. Агент включает консоль (`console_target`): Windows по `claude_pid`; Unix только если `CCTG_RUN` прошёл `launched_by` и сокет этого `cctg run` отвечает на `"screen"`. Иначе `console_keys/commands = false`, hub отвечает как сейчас (новый текст `NO_CONSOLE_NOTICE`). Без терминала (`claude-cctg -p ... | jq`, тесты) `cctg run` запускает claude по-старому.
7. macOS: `proctree::macos` через `proc_pidinfo(PROC_PIDTBSDINFO)` (ppid, `pbi_name`/`pbi_comm`, время старта: родитель, начавшийся позже потомка, обрывает цепочку) и `proc_pidpath`; список процессов `proc_listallpids`. Имя нативного claude на macOS это номер версии (путь `~/.local/share/claude/versions/<версия>`, anthropics/claude-code#12433), поэтому `process_name` называет `claude` файл в папке `claude/versions`. Это чинит на macOS `claude_pid` агента, вложенные `claude -p`, перепривязку после `/clear`, уборку сессий (TASK-039) и чистку ссылок shim.

Зависимости: `vt100 = "0.16"` (0.16.2, MIT, тянет `vte` 0.15, `arrayvec`, `unicode-width`; `itoa`, `memchr` уже в lock) обычной зависимостью на всех ОС, чтобы тесты `term::Screen` шли и на Windows; `libc` переезжает из unix dev-dependencies в unix dependencies (уже в lock).

## 4. Risk areas

- Unix-код не собирался здесь. Места, где вероятнее ошибка компиляции или clippy на CI: приведение `TIOC*` (`as _`: на Linux `Ioctl` = `c_ulong`/`c_int` у musl, на macOS `TIOCSCTTY` это `c_uint`), указатели `openpty` (Linux `*const termios/winsize`, macOS `*mut`: переданы `&mut`, в тесте `null_mut::<libc::termios>()`), `cfmakeraw` возвращает `c_int` или `()` по платформе (стоит в блоке с `;`), `clippy::zombie_processes` в тесте (подавлен с `reason`), `vec![0; n]` вместо `0 as c_int` (clippy `unnecessary_cast`). Правило разбора красного CI в разделе 6.
- Тайминги e2e на медленных раннерах macOS: все ожидания до 20 с, опрос 50 мс; `keys::*` сами ждут 0.4-3 с. Флак возможен в месте resize (SIGWINCH доходит асинхронно; тест ждёт события размера до 20 с).
- Настоящий Claude Code в pty не проверен (здесь нет Unix). Живые проверки для пользователя: (1) диалог каналов отвечается сам и канал поднимается (сообщение из темы доходит) при каждом старте и перезапуске; (2) `!echo hi` из темы переводит поле в bash-режим (текст уходит первым символом отдельно; если нет, `box_shows` всё равно увидит `❯ !echo hi` и отправит это промптом, что хуже, см. вопрос 3); (3) Backspace (DEL) стирает набранное при черновике; (4) Ctrl+Z/`fg`, изменение размера, выход и код выхода как без cctg; (5) на Mac вложенный `claude -p` не создаёт тему (проверка `process_name`).
- Байтовое смешение: символы пользователя и агента могут чередоваться между запросами агента (как и на Windows). Внутри одной записи смешения нет (общий мьютекс master).
- `vt100` может расходиться с реальным терминалом на экзотических последовательностях (синхронный вывод DEC 2026, kitty keyboard): неизвестные режимы игнорируются, ответы на запросы терминала даёт настоящий терминал (байты идут насквозь). Паника эмулятора выключает только копию.
- Путь сокета: `sun_path` 104 байта на macOS, 108 на Linux. `~/.cctg/run/<pid>.sock` короткий; длинный `CCTG_STATE_DIR` даёт одну строку «no terminal socket» и работу без консольных кнопок (диалог каналов всё равно отвечается).
- Раздел `cctg run` в raw-режиме: если процесс убит SIGKILL, терминал остаётся raw (как у любой TUI); лечится `reset`. SIGTERM/SIGHUP обработаны.
- Поток `relay_input` держит stdin до выхода процесса; `std::process::exit` в `main` его гасит (как у агента).
- Пересечение с TASK-050 (идёт на `feature/update-download`): `agent.rs` (050 правит доки модуля около стр. 46 и `serve_channel`; эталон правит доки стр. 26-35, `run_stdio` 486-514 и добавляет `console_target` перед `LinkPlan`: соседние, но разные строки), `lib.rs` (050 добавляет `pub mod download;` в другом месте списка), `docs/remote-hub.md` (050 правит стр. 134, эталон 105). `update.rs`, `run.rs`, `keys.rs`, `Cargo.toml` 050 не трогает. Если 050 сольётся первым, патч применяется с `git apply -3` или руками по hunks; хеши `agent.rs`, `lib.rs`, `docs/remote-hub.md`, `Cargo.lock` тогда будут другими, остальные совпадут.

## 5. Open questions

1. Ctrl+Z: эталон повторяет остановку claude (`cctg run` останавливается сам и продолжает с `fg`). Если пользователю это не нужно, шаг можно убрать (`waitpid` без `WUNTRACED`), тогда Ctrl+Z claude внутри pty «замораживает» окно. Рекомендация: оставить.
2. tmux-путь для claude, запущенного без `claude-cctg`: не делаем (перезапуск всё равно невозможен). Подтвердить.
3. Разбиение набора «первый символ, 50 мс, остальное» (агент, `keys::Run::write`) закрывает неизвестное: как Claude Code понимает `!` в пачке символов. Если живая проверка покажет, что пачка работает, разбиение можно убрать; если и отдельный `!` не включает bash-режим, нужен отдельный разбор (как на Windows, TASK-043).
