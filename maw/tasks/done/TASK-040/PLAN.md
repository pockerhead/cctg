Исследование: Microsoft Learn, `SetConsoleCtrlHandler` (https://learn.microsoft.com/en-us/windows/console/setconsolectrlhandler): «If the HandlerRoutine parameter is NULL, a TRUE value causes the calling process to ignore CTRL+C input... This attribute of ignoring or processing CTRL+C is inherited by child processes». Поэтому `cctg run` не зовёт `SetConsoleCtrlHandler(NULL, TRUE)` (claude унаследовал бы игнор Ctrl+C), а только слушает `tokio::signal::ctrl_c`/`ctrl_break` (обработчик-функция возвращает TRUE, список обработчиков не наследуется). ## 2. Approach

Пять частей, всё умное в hub и рабочем агенте, прослойка и два лаунчера тупые.

1. **Версия клиента.** `crate::client`: `build_of(path)` = sha256 файла (hex), `own_build()`, `VERSION = CARGO_PKG_VERSION` (он всегда `0.1.0`, поэтому сравниваются сборки). sha256 из `aws-lc-rs::digest` (уже собирается для rustls через reqwest с теми же фичами, скачивания нет). `Register.client: Option<Client {version, build, self_update, restartable}>` (одно поле, опционально, без bump). `HookPost.client_version` (только версия, без хеша: хук каждый раз запускается заново из пути в settings, его хеш по построению равен новейшему, а чтение 9 МБ на каждый хук даром; решение в `log.jsonl`). Hub считает свою сборку при старте; агент «устарел», если его `build` отличается от сборки hub или клиента нет вовсе. Лог: `info!` «agent runs another cctg build» с короткими хешами.
2. **Прослойка `cctg agent`** (`shim.rs`, ~200 строк): держит stdio Claude Code, запускает `cctg agent-worker` из пути, с которого стартовала сама (после `cctg deploy` там новая сборка), с `CREATE_NO_WINDOW`, env `CCTG_SHIM=1`, `CCTG_SHIM_STARTED=<unix s>`, для второго и далее `CCTG_WORKER_RESUMED=1`, и копирует строки в обе стороны. Протокола MCP не знает: строка `{"cctg_shim":"switch"}` от рабочего означает «перестань мне писать и закрой мой stdin», код выхода 75 означает «я передал дела». Строки Claude Code, пришедшие в это время, копятся и уходят новому рабочему по порядку; строки рабочего пишутся целиком (обрывок без `\n` выбрасывается). Рабочий, упавший при живом Claude Code, запускается снова через 1 с, не больше 3 раз в минуту. Конец stdin Claude Code → закрыть stdin рабочего → дождаться → выйти 0. Отвергнуто: повтор `initialize` силами прослойки (нужен разбор MCP в неизменяемом процессе) и переключение только по коду выхода (теряет строки в трубе).
3. **Рабочий агент на `update`** (`update.rs` + `agent::serve_channel`): считает план (`Worker::plan`, блокирующий): (а) файл, из которого он запущен, имеет другой sha256 → **Reload**: пишет switch-маркер, отвечает на все строки, что прослойка ещё отдаст, по концу stdin шлёт hub `update_answer reloading`, ждёт `released` (≤5 с), выходит 75; (б) иначе, если после старта прослойки изменились файлы `--settings`/`--mcp-config` из `CCTG_RUN_ARGS` (mtime > `CCTG_SHIM_STARTED`) или прослойка старее `MIN_SHIM_LEVEL` → **Restart** при `restartable` (есть `CCTG_RUN`, известен claude pid, есть state dir, Windows) или **NeedsManualRestart**; (в) иначе **UpToDate**. Restart: `update_answer restarting` → `released{session_id}` (сессия, к которой hub привязал агента, после `/clear` это не env id) → файл-заявка `<state>/restart/<pid cctg run>.json` `{"session_id"}` → `keys::type_exit` (набрать `/exit`, прочитать поле, Enter только при `❯ /exit`, иначе 5 Backspace и заявка удаляется) → ждать конца stdin до 20 с, иначе заявку убрать и ответить `failed`. Черновик в поле → `update_answer draft_in_input`. Новый рабочий начинает с `Server::initialized()`: второго `initialize` не будет.
4. **Hub** (`slots.rs`, `status.rs`, `registry.rs`): устаревший живой текущий агент слота даёт одно предупреждение в тему на сборку hub (`SessionEntry.update_warned`, в `registry.json`) с кнопкой `update:<session>`, а в закрепе строку «⬆️ Клиент cctg устарел» и кнопку `status:update` рядом с ⏹. Ничего не шлётся без нажатия. Нажатие (callback только от allowlist, как все): агент без `self_update` → «перезапустите вручную»; иначе запись `UpdateAsk`, и `pump_updates` шлёт `update` только когда ход не идёт (`Activity::busy`); ответ «Идёт ход: обновлю, когда он закончится (⏹ прервёт его)». Ответ `reloading`/`restarting`: conn помечен `leaving`, отвязан от сессии сразу (новые сообщения ждут в буфере слота), ему уходит `released` за всем, что уже в его очереди (FIFO связи), следующий агент сессии спрашивается снова (до 3 раундов за 120 с, не тому же conn). `up_to_date`: «✅ Клиент cctg обновлён» или «на машине нет новой сборки» (если всё ещё устарел). `draft_in_input`/`needs_manual_restart`/`failed`: уведомление, уходящий conn привязывается обратно. `ingress.rs` пропускает `UpdateAnswer`.
5. **`cctg run [-- <args>]`** (`run.rs`, ~100 строк без тестов): claude дочерним процессом в той же консоли, env `CCTG_RUN=<свой pid>`, `CCTG_RUN_ARGS=<JSON аргументов>`; после выхода claude берёт `<state>/restart/<свой pid>.json` (удаляет, id только `[A-Za-z0-9-]{1,64}`), запускает `claude --resume <id>` с теми же аргументами без `-c/--continue/-r/--resume <id>/--session-id <id>/--fork-session` и отвечает Enter на диалог каналов, если выбран пункт 1; без заявки выходит с кодом claude. Устаревшая заявка своего pid удаляется на старте. Программу claude можно подменить `CCTG_CLAUDE` (тесты).
6. **Supervisor упрощён** (`supervise.rs` ~150 строк, цикл ~50): старт hub, ожидание, перезапуск по выходу (backoff 1..60 с) или сразу по файлу `cctg.restart`, отметка `cctg.hub-started` (`<pid> <nanos>`), Ctrl+C. Проверка сборки, подмена файлов, пробный срок и откат переехали в `cctg deploy` (`deploy.rs`): `--version`, сравнение байт, `current→old`, копия `.part→current`, `cctg.restart`, ждать новую отметку, спать `trial+2 с`, новая отметка в сроке = упал → `current→bad`, `old→current`, ещё один `cctg.restart`. Откат не потерян, но требует, чтобы `deploy` дождался конца (он и так ждёт). `--trial-secs` переехал в `deploy`. Протокол `cctg.next`/`deploy-id`/`deploy-result` ушёл.

## 4. Risk areas

- **Порча черновика.** Если поле ввода изменится между чтением и Enter (пользователь печатает в эти ~0.4 с), Enter уйдёт с его текстом. Окно маленькое, restart идёт только по кнопке и вне хода. Если Claude Code поменяет вид поля (глиф, линии), `box_is_exit` скажет «черновик» и откажет, то есть сломается в безопасную сторону.
- **Сообщение между `released` и `/exit`.** hub отвязывает агента по `restarting`, но сообщение, отданное до этого, может начать ход; тогда `/exit` ляжет в очередь хода. hub шлёт `update` только вне хода, окно ~доли секунды.
- **Ложное «не устарел».** Только изменённые настройки без новой сборки hub не видит (сравнивает сборки), предупреждения не будет, пока не выйдет новая сборка. На практике настройки меняются вместе с deploy.
- **Стоимость хеша.** Рабочий хеширует свой exe на старте (release ~9 МБ, мс; debug-бинарник тестов десятки МБ, ~0.1-0.2 с), и при каждом `update` файл на диске. Hub один раз на старте.
- **Прослойка вечна для сессии.** Её баг чинится только перезапуском claude; поэтому в ней нет ничего, кроме строк, маркера и кодов. `MIN_SHIM_LEVEL` оставлен как шов: поднять его = потребовать перезапуск.
- **Сломанная новая сборка агента.** Падает на старте → прослойка перезапускает до 3 раз в минуту и выходит; Claude Code теряет канал до перезапуска сессии. `deploy` проверяет `--version`, но не работу агента.
- **Откат в `deploy`.** Если `deploy` прервать во время пробного срока, отката нет (раньше его делал supervisor). Упавший hub supervisor всё равно перезапускает с backoff. Заявка `cctg.restart` читается только пока hub запущен (во время backoff не читается), `deploy` ждёт до `--timeout-secs`.
- **Позиционный промпт** в аргументах `claude-cctg` при перезапуске уйдёт ещё раз (`resume_args` его не отличит от значения флага). Записано в docs.
- **Консоли.** Рабочий стартует с `CREATE_NO_WINDOW`; `keys::type_exit` и `press` отцепляются от своей консоли и цепляются к консоли claude, окна не появляются. `cctg run` не создаёт консолей, `claude` наследует текущую.
- **Флак.** На эталоне один раз упал `hub::slots::tests::a_nested_answer_survives_a_restart_before_its_end` (ждёт сохранения registry 300 мс под нагрузкой полного прогона), три повторных прогона `--lib` чистые; к задаче не относится (не трогает nested-блоки), в QA не принимать за регрессию.
- Секреты: новые логи несут короткие хеши сборок и id сессий, без путей; заявка содержит только id сессии; `CCTG_RUN_ARGS` в env claude содержит пути файлов конфигурации (не секреты, они и так в командной строке claude).
