# PCTX proposals — TASK-040

- 2026-09-24 (planner, channel domain): after TASK-040 `cctg agent` is a stdio shim (`shim.rs`) and the channel server runs as its child `cctg agent-worker` (`agent::run_stdio`). The shim knows only lines, the switch marker `{"cctg_shim":"switch"}` and exit code 75; the worker hands over on the hub's `update` (drain stdin, `update_answer reloading`, wait for `released`, exit 75) and a resumed worker starts with the channel initialized (env `CCTG_WORKER_RESUMED`). Proposed invariant for channel.md: "stdout of the worker may carry the switch marker line, which the shim never forwards; anything else on it is JSON-RPC". Why: agents that miss this break the transport or the hand-over.
- 2026-09-24 (planner, channel domain, VERIFIED by probe P1/P2 on 2.1.281): a running interactive session does not reload its `--settings <file>` (statusLine, a changed hook, a hook for a new event: none). `/exit` + Enter typed with `WriteConsoleInputW` from the MCP child exits claude (code 0, `SessionEnd reason=prompt_input_exit`); an unsent draft in the input box is submitted together with it as one prompt (`draft text/exit`). Claude Code renders the input box as `❯` + U+00A0 + text between the last two `─` rules. Why: the hooks-domain lesson "settings.json hook changes are picked up" (TASK-003) does not hold for `--settings` files; worth a line so nobody relies on it.
- 2026-09-24 (planner, hub domain): client versions. `Register.client {version, build (sha256 of the exe), self_update, restartable}` and `HookPost.client_version` are optional; the hub compares `build` with its own; outdated = other build or no client. One warning per hub build (`SessionEntry.update_warned`), a status line plus `⬆️ Обновить`; `update` goes out only after an allowlisted press and only when no turn runs; `update_answer` reloading/restarting unbinds the agent and is answered with `released` behind its queue. Proposed as a TASK-040 bullet for hub.md.
- 2026-09-24 (planner, hub domain, launchers): `cctg supervise` now only starts, waits, restarts on exit or on `cctg.restart`, and stamps `cctg.hub-started`; checks, swap and rollback live in `cctg deploy`, which must stay running for the rollback. Proposed to extend the "Launchers stay dumb" bullet with this split.
- 2026-09-24 (plan-reviewer-2, risk lesson): with one shared `CARGO_TARGET_DIR` for several worktrees, `target/debug/cctg.exe` (the `CARGO_BIN_EXE_cctg` of process tests) is one file for all of them: another worktree's build overwrote it mid-run and `run_e2e`/`update_e2e`/`spool_e2e`/`supervise_e2e` failed against a foreign binary (no `run` subcommand, no `client`). Per-crate artifacts under `deps/` do not collide, the uplifted bin does. Proposed lesson: a process-test failure that looks like a missing feature is first re-run alone after `cctg.exe --help` shows the expected subcommands.
- 2026-09-24 (plan-reviewer-2, launchers): extend "Launchers stay dumb" with "knowledge of claude's CLI options (which words are values, which the prompt) lives in the worker agent; `cctg run` runs the argument list of the restart request as is". Why: a claude option table in a launcher that is never updated goes stale with claude.
- 2026-09-24 (code-reviewer, universal crate list): `aws-lc-rs` (sha256 of the cctg exe, TASK-040 `client.rs`) is now a direct dependency of `crates/cctg`; it was already built transitively for rustls. Proposed: add it to the agreed crate set in the code-reviewer tooling line, noting it is tied to the rustls backend. Why: the list is checked by review and currently flags it.


## 2026-09-24 (fixer): a fresh copy of an exe starts slowly on Windows

Domain: channel (risk lesson). A freshly copied `cctg.exe` (new file, new name) takes about 0.5 s longer to start the first time (debug build: `cctg agent` answered `initialize` after 1.2 s instead of 0.06 s), because Windows scans the new file; a hard link to the same file starts in 0.017 s (`scratch/fixer/link_vs_copy.py`). Anything that starts an agent from a copy (shim workers, test stand-ins) should use a hard link on the same volume. Why: timing tests (`agent_stdio`) failed with copies.
