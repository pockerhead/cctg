## 1. Summary

Клиент cctg на машине с claude узнаёт от hub, что устарел, и обновляется только по нажатию «⬆️ Обновить» allowlisted-пользователем. `cctg agent` становится тупой stdio-прослойкой (`shim.rs`: строки, один маркер `{"cctg_shim":"switch"}`, код выхода 75), которая держит stdio Claude Code и запускает рабочий агент `cctg agent-worker` дочерним процессом; по `update` от hub рабочий либо передаёт дела новому бинарнику на том же пути (прослойка копит строки Claude Code и отдаёт их новому рабочему, `initialize` не повторяется), либо, если изменились файлы `--settings`/`--mcp-config` (claude их на лету не перечитывает, проба P1), пишет заявку с готовой командной строкой перезапуска и набирает `/exit` с проверкой поля ввода (проба P2), а `cctg run -- <аргументы claude>` (тупой лаунчер, обёртка `claude-cctg`) запускает claude заново в том же окне по заявке и отвечает Enter на диалог development channels. Версия: `Register.client {version, build=sha256 exe, self_update}` и `HookPost.client_version`, оба опциональны, без bump `wire::VERSION`; hub сравнивает сборку агента со своей, шлёт одно громкое предупреждение на сборку hub в тему сессии и показывает строку и кнопку в закрепе. `cctg supervise` сокращён до «старт, ожидание, перезапуск по выходу или по файлу `cctg.restart`, отметка старта»; проверка, подмена и откат бинарника переехали в `cctg deploy`.
