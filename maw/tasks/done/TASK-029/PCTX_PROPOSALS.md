# PCTX proposals — TASK-029 (planner)

- 2026-09-24 (channel/hooks, verified by probe `scratch/planner/probe/probe.esc_text.out.txt`, 2.1.281): Esc written into the claude console from its stdio MCP child (`FreeConsole` + `AttachConsole(parent pid)` + `CreateFileW("CONIN$")` + `WriteConsoleInputW`) cancels the running turn like the keyboard. The MCP server runs with its own windowless console (`GetConsoleWindow()==0`, process list 1), so `FreeConsole` first is required. An interrupt fires no `Stop` hook, and an interrupt during thinking leaves no `[Request interrupted by user]` record at all (the prompt goes back into the input box): the end of such a turn is known only to whoever pressed Esc.
- 2026-09-24 (hooks): Claude Code command hooks take `"async": true` (runs in the background, not waited for, `timeout` not enforced; in `-p` killed at teardown). Good for per-tool-call status hooks: ~10 ms per process with a live hub, ~313 ms with the hub down, neither on Claude Code's critical path (`scratch/planner/hook_cost.out.txt`).
- 2026-09-24 (process): the auto-mode classifier denied a planner subagent's self-driven hidden-console `claude` probe ("Tmux Self Drive") even under the README rule; the orchestrator ran the same scripts after the user approved. Plan such probes as a user-approved orchestrator step from the start.
- 2026-09-24 (hub): `docs/hook-settings.json` is pinned by `crates/cctg/tests/hook_cli.rs::settings_snippet_registers_every_event_without_secrets_or_paths`; a hooks/statusLine change there must update that test in the same patch.
- 2026-09-24 (hub, plan review; Telegram Bot API `Message.pinned_message`): a pin service message is not intrinsically bot-authored—an administrator can pin the same message too. Never bypass attribution merely because a message is a service kind. Delete a `pinned_message` notice only when its sender is this bot (or when it is correlated to the bot's pending pin operation); otherwise leave it untouched.
- 2026-09-24 (channel, plan review; Win32 `WriteConsoleInputW`): a successful write reports only that input records entered the console buffer, not that Claude Code consumed Esc or ended its turn. Do not transition turn state to idle from the Win32 return value; wait for an independent lifecycle/transcript signal. In particular, Esc at an open permission dialog can answer the dialog without stopping the agentic turn.
- 2026-09-24 (hooks/statusline, plan-reviewer-2; https://code.claude.com/docs/en/statusline troubleshooting): a statusLine command that exits non-zero or prints nothing blanks the status line. A wrapper that chains the user's statusLine (cctg statusline) must pass its stdout byte for byte AND its exit code, or the terminal stops matching what the user had without cctg.
- 2026-09-24 (hub, fixer): terminal answers to permission prompts are inferred, not seen. A ToolStart/ToolEnd hook of the same session that reaches the hub at least `PROMPT_SETTLE` (2 s) after a prompt came in quiets that prompt (icon and status ⏹ gate); younger hook events and stream lines never do, because async PostToolUse of the previous call and stream lines (unbounded lag) arrive after the next call's prompt. Known limit: a parallel call (concurrent Read/Agent) that ends 2 s+ after a sibling's prompt quiets it too early.
