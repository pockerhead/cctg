# TASK-050: «Обновить» downloads the client release itself

Type: feature
Mode: small-fix
Priority: high
Branch: feature/update-download
Domains: hub, channel

## Description
Решение пользователя 2026-09-25. Сейчас «Обновить» (TASK-040) только подхватывает новую сборку, уже лежащую в `~/.cctg/bin`; на удалённых машинах её надо сначала поставить `install.sh` нового тега. Нужно: по нажатию «Обновить» агент сам скачивает сборку той версии, что у hub, и дальше идёт прежним путём (замена воркера, при необходимости перезапуск claude, TASK-047 защиты).

- hub знает свой релизный тег (из сборки: `CCTG_RELEASE`/тег в CI и Docker; без тега у локальной сборки — скачивания нет, прежнее поведение) и передаёт его в `update` устаревшему агенту (новое необязательное поле, без VERSION bump).
- Агент: если на диске не та сборка, что у hub, скачивает `cctg-<tag>-<triple>[.exe]` и `SHA256SUMS` того же релиза из GitHub Releases (URL-база настраивается, как `CCTG_INSTALL_BASE_URL` у `install.sh`; https, через системный/`HTTPS_PROXY` прокси), сверяет sha256, кладёт в `~/.cctg/bin` заменой через переименование (Windows: запущенный exe переименовывается, как `install.sh`/`cctg deploy`), только потом идёт замена воркера. Ошибка сети, несовпадение суммы, неизвестная платформа → понятный ответ в теме, старая сборка на месте. Скачивание только по нажатию кнопки, никогда само.
- Триплеты те же, что в релизе (x86_64-pc-windows-msvc, x86_64-unknown-linux-musl, aarch64-apple-darwin; macOS после записи — codesign ad-hoc, как в update_e2e, если нужно для запуска).
- Логи без токенов и полных URL с секретами (URL релиза публичный, его можно).

## Acceptance criteria
- [ ] «Обновить» на устаревшем клиенте скачивает сборку тега hub, проверяет SHA256SUMS, ставит и подхватывает её (e2e с локальным фейковым релизом по http на loopback, как install_e2e)
- [ ] несовпадение суммы / нет сети / нет ассета: понятный ответ в теме, старая сборка работает
- [ ] hub без тега и старый агент без capability: прежнее поведение
- [ ] Existing tests pass
