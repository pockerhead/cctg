# TASK-027: Telegram formatting of markdown text

Type: feature
Mode: small-fix
Priority: high
Branch: feature/telegram-formatting
Domains: hub, transcript

## Description
Ответы, строки стрима и размышления модели приходят в Telegram сырым markdown (`**`, `` ` ``, ```блоки```, заголовки `#`, списки), форматирование не видно. Переводить markdown в Telegram HTML (`parse_mode: HTML`: `<b>`, `<i>`, `<code>`, `<pre>`, `<a href>`, `<blockquote>`; заголовки в жирный, списки как есть; всё остальное экранировать `& < >`) для текста ассистента (ответ хода, текст в стриме, 💭) и для brief/full по желанию. Лимит 4096 считается по тексту после разметки; разбивка `split_for_telegram` не должна резать тег (делить до конвертации и конвертировать каждый кусок так, чтобы теги закрывались в пределах куска). Если Telegram отвечает `400 can't parse entities`, то же сообщение уходит повторно без `parse_mode` исходным текстом (один раз), чтобы ничего не терялось. Строки вызовов инструментов, служебные тексты и кнопки не менять (или только `<code>` для имён — решить). Без новых тяжёлых крейтов: `pulldown-cmark` допустим, если он маленький и без лишних фич, иначе простой свой конвертер для подмножества.

## Acceptance criteria
- [ ] жирный, курсив, inline code, блоки кода с языком, ссылки, заголовки и списки из реального ответа модели рендерятся в Telegram HTML; спецсимволы экранированы
- [ ] длинный текст режется на куски не длиннее лимита, каждый кусок валидный HTML (теги закрыты)
- [ ] `can't parse entities` даёт одну повторную отправку тем же текстом без разметки
- [ ] тесты на конвертер (фикстуры из реальных ответов) и на путь отправки с фейковым Telegram
- [ ] Existing tests pass
