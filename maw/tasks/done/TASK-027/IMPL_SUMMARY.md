# TASK-027 — IMPL_SUMMARY

Режим small-fix, плана нет, реализовано по спецификации. Код в коммите `2372607` на `feature/telegram-formatting`.

## 1. Что сделано

Дизайн: сообщение в очереди несёт исходный текст и, для markdown, его HTML. Отправка идёт HTML с `parse_mode: HTML`; если Telegram отвечает `400 can't parse entities`, scheduler снимает HTML и ставит ту же задачу в голову своей очереди, она уходит ещё раз исходным текстом. Второй раз HTML уже нет, поэтому повтор ровно один. Повтор тратит токен бакета, как обычная отправка, и не обгоняет ничего в своей теме.

Конвертер (свой, без `pulldown-cmark`: `tests/purity.rs` фиксирует зависимости `transcript`):
- `**b**`/`__b__` -> `<b>`, `*i*`/`_i_` -> `<i>`, `~~s~~` -> `<s>`, `` `code` `` -> `<code>`, fenced блок -> `<pre><code class="language-x">` (без языка `<pre>`), `[t](url)` -> `<a href>` только для `http(s)://`, `tg://`, `mailto:`, `#` заголовки -> `<b>`, `>` строки -> `<blockquote>`. Списки, таблицы, `---` как есть. Остальное экранируется `& < >`.
- `_` внутри слова не размечает (`snake_case`), `2 * 3 * 4` остаётся текстом, незакрытый разделитель остаётся текстом.
- Теги строятся рекурсивно парой вокруг содержимого, поэтому любой кусок всегда закрыт. Инлайн разметка не переходит через перевод строки.
- Разбивка: режет исходник (`cut` из `split.rs`), конвертирует кусок, и если HTML длиннее 4096 (UTF-16, `telegram_len`), уменьшает лимит и режет снова. Блок кода, открытый в конце куска, закрывается в нём и открывается заново в начале следующего. Куски с пустым HTML (голый ```` ``` ````) выбрасываются. `prefer_file` как у `split_for_telegram`.

Что форматируется: ответ хода из `Stop` (и потоковый, и обычный), текст `reply` (общий `send_text`), текст ассистента в стриме, 💭. Что остаётся как было: `> промпт`, строки инструментов, уведомления, кнопки, permission-запросы, блоки субагентов, `/brief` и `/full`, документы. Решение про имена инструментов: `<code>` не добавлял, строки инструментов остались plain. Склейка в стриме: если в объединённое сообщение попадает хоть одна HTML-строка (например 💭 между строками инструментов), сообщение целиком HTML, plain-строки в нём экранированы; фолбэк тогда шлёт склеенный plain-текст.

## 2. Отклонения

- `/brief` и `/full` не форматирую (в спецификации "по желанию"): там промпты пользователя и строки инструментов, это не markdown модели, `*` в промпте превратился бы в курсив.
- Фикстура "из реальных ответов": вытащить ответы из `~/.claude/projects` не дал классификатор разрешений (записано в `log.jsonl` как dead_end). Взял реальный текст модели из репозитория, `IMPL_SUMMARY.md` задачи TASK-004: заголовки, жирный, inline code, блоки с языком и без, списки, таблица. Ссылки и цитаты покрыты табличным тестом.
- Не сделано: заголовок или список, начинающийся внутри длинной строки, которую пришлось разрезать посреди строки, во втором куске не распознаётся (строки больше 4096 символов, на практике не встречаются).
