# TASK-027 — FIX_SUMMARY

Код в коммите `eea833e` на `feature/telegram-formatting`. Все шесть пунктов ревью проверены по коду и подтвердились. Для каждого есть тест.

Проверка перед правкой: самым рискованным был совет из п.6 ревью ("запомнить, что закрывающего разделителя дальше нет"). Поиск `closing` от позиции монотонен, так что сам по себе совет не ломает код. Но он не закрывает остальные квадратичные сканы: `code_end` внутри `closing`, `link` (`find(']')`), `autolink` (`find('>')`). Поэтому сделал общий бюджет шагов (п.5).

## 1. Fixed

1. **Бэкслэш и Windows-пути** (`markdown.rs`: `ESCAPABLE`, `path_word`, ветка `\\` в `inline`). Правило: бэкслэш экранирует только символы, которые конвертер читает как разметку (`` \ ` * _ ~ [ ] # < > ``). Перед всем остальным он остаётся текстом (`\.`, `\U`). Внутри слова (до пробелов), похожего на Windows-путь, бэкслэш тоже остаётся: путь это слово с `X:\` или с бэкслэшем перед буквой или цифрой. Следующий символ и там не считается разметкой. Итог: `C:\Users\user\.claude\projects`, `C:\dev\_x and y_`, `D:\_build\*.rs`, `\\server\share\_x` остаются как написаны, а `my\_var`, `\*x\*`, `\# не заголовок` теряют бэкслэш, как в CommonMark. Решение записано в log.jsonl. Тест: `windows_paths_keep_their_backslashes_outside_code`.
2. **Скобки в URL** (`link`): URL заканчивается на `)` при нулевой глубине скобок. `[wiki](https://en.wikipedia.org/wiki/Rust_(language))` даёт `href=".../Rust_(language)"`, а незакрытая скобка оставляет всю конструкцию текстом. Тест: `links_keep_balanced_parentheses_in_the_url`.
3. **Fence без закрытия** (`Closers`, `render`): блок открывается, только если ниже в сообщении есть закрывающая строка (только тот же маркер, не короче открывающего). Строки-кандидаты считаются один раз по всему сообщению: смещения и суффиксный максимум длины, поиск через `partition_point`. Проверка идёт по всему тексту, а не по куску: `split_markdown_for_telegram` конвертирует куски, и закрытие может быть в следующем. Одиночная строка `~~~~~~~~` и незакрытый ```` ``` ```` остаются текстом. Тест: `a_fence_opens_a_block_only_when_it_closes_later` (в том числе блок, закрытый в следующем куске). Старое ожидание `"```py\nprint(1)"` → `<pre>` заменено на текст.
4. **Цитата** (`quoted`): цитата это `>` плюс пробел или таб, либо голая строка `>`. `>= 5 items` и `>>x` остаются текстом. Тест: `a_quote_needs_a_space_after_the_marker`.
5. **Квадратичный поиск** (`spend`, `STEPS_PER_BYTE = 32`, `MIN_STEPS = 1024`): бюджет на строку. Его тратят итерации `inline`, `closing`, `code_end`, сканы `link` и `autolink`. Когда бюджет кончился, остаток строки идёт экранированным текстом, HTML остаётся валидным. Работа на строку линейна. Обычный текст бюджет не выбирает: 20 незакрытых `*` перед `**done**` всё равно дают `<b>done</b>`. Тест `pathological_input_converts_in_bounded_work` прогоняет девять патологических входов по 60k символов в одну строку через `markdown_to_html` и `split_markdown_for_telegram`, проверяет валидность, лимит и склейку исходника. Весь бинарь с этим тестом идёт 0.76 с в debug.
6. **Повтор без HTML не склеивается снова** (`scheduler.rs`: `Job.plain_retry`, `merge_lines`, `dispatch`). После `can't parse entities` job помечается `plain_retry`, и `merge_lines` его больше не расширяет. Строки, склеенные при первой попытке, уходят вместе с ним. Так на каждое исходное сообщение ровно один повтор. Тест: `a_plain_retry_never_merges_formatted_lines_back_into_html`. Пять HTML-строк, пять токенов: без фикса повтор забирал строки 1-4 и становился HTML. Проверено временным отключением guard: тест падает, после возврата guard проходит.
