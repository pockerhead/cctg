# TASK-049: heartbeat on the agent link

Type: bugfix
Mode: small-fix
Priority: high
Branch: fix/link-heartbeat
Domains: hub, channel

## Description
Найдено вживую 2026-09-25 после переезда hub на удалённый сервер (TLS через интернет): TLS-соединение агента простояло без трафика около часа, в 16:15Z hub увидел обрыв (`agent disconnected`), а агент не заметил и 32 минуты не переподключался (claude жив, хуки шли на сервер, `SessionEnd` не было); помог только ручной перезапуск сессии. Причина по картине: полуоткрытый сокет после того, как промежуточный NAT/туннель выкинул простаивающее соединение; на agent-линке нет ни прикладного heartbeat, ни TCP keepalive. На localhost это не проявлялось.

Сделать: прикладной heartbeat на agent-линке в обе стороны за capability (без VERSION bump; старый пир без capability не получает пингов и работает как раньше): каждая сторона шлёт ping при тишине дольше интервала (около 30 с) и считает линк мёртвым, если от пира ничего не пришло дольше таймаута (около 90 с): агент рвёт соединение и идёт в обычный reconnect (TASK-021/040), hub отвязывает агента как при обрыве. Плюс TCP keepalive на сокетах обеих сторон (socket2 или tokio: время простоя порядка 30–60 с), чтобы NAT держал соединение. Интервалы — константы, тесты используют укороченные. Логи: переподключение по таймауту heartbeat одной строкой info/warn.

## Acceptance criteria
- [ ] агент, у которого hub перестал отвечать (соединение молчит, но не закрыто), за таймаут рвёт линк и переподключается (тест с «замороженным» фейковым hub)
- [ ] hub отвязывает агента, от которого ничего не приходит дольше таймаута (тест)
- [ ] пинги только к пиру с capability; старый hub/агент без неё работают как раньше
- [ ] TCP keepalive включён на сокетах агента и hub (проверка через socket2 в тесте или обоснование)
- [ ] Existing tests pass
