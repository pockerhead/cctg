# TASK-026: hub supervisor and self-deploy

Type: feature
Mode: small-fix
Priority: high
Branch: feature/hub-supervisor
Domains: hub

## Description
Пользователь хочет просить изменения в cctg из самой сессии через Telegram, а оркестратор должен выкатывать их сам, без ручного перезапуска hub. Нужен `cctg supervise`: держит `cctg hub` запущенным (перезапуск при падении с backoff), следит за файлом-кандидатом `<bin dir>/cctg.next.exe` (или аналог на других ОС); когда он появился и проходит проверку (`cctg.next.exe --version` отвечает и версия/хеш отличаются), supervisor останавливает hub мягко (hub дожидается сохранения реестра), переименовывает текущий exe в `cctg.old.exe`, ставит новый на место и запускает hub заново; если новый hub падает в первые N секунд, откатывается на `cctg.old.exe` и пишет об этом. Мягкая остановка hub: сигнал через файл или локальный HTTP/TCP-запрос с секретом, без убийства процесса посреди записи. Deploy-команда для оркестратора: `cctg deploy <path-to-built-exe>` кладёт кандидата и ждёт результата (успех / откат) с таймаутом. Агенты (`cctg agent`) уже переподключаются к hub сами; хуки запускают exe заново при каждом событии — проверить, что во время подмены они не ломаются (exe на месте, пока старый работает, Windows не даёт перезаписать запущенный файл, но даёт переименовать). Логи supervisor без секретов.

## Acceptance criteria
- [ ] `cctg supervise` запускает hub, перезапускает его после падения (backoff, без шторма), корректно завершается сам по Ctrl+C вместе с hub
- [ ] `cctg deploy <exe>` подменяет бинарник и перезапускает hub без потери реестра; агенты переподключаются (тест с настоящими процессами, фейковый Telegram или без Telegram)
- [ ] битый кандидат (не запускается или hub падает сразу) приводит к откату на старый exe, деплой сообщает об ошибке
- [ ] docs/poc.md описывает запуск через supervisor и деплой
- [ ] Existing tests pass
