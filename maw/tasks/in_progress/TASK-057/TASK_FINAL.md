# TASK-057: console commands refused because of a prompt suggestion in the input box

Type: bug
Mode: small-fix
Priority: high
Branch: fix/console-ghost-text
Domains: hub, console

## Description
Найдено вживую 2026-09-26 на Linux (cctg run в tmux, Claude Code 2.1.28x, скрин `scratch/linux-ghost.jpg`): команда из Telegram (`! curl ...`) трижды отказана «В поле ввода терминала есть неотправленный текст», хотя поле пустое. В поле стоит серая подсказка Claude Code (prompt suggestion, ghost text): `❯ Да, давай T2I`. Экран (`keys.rs`: `input_box`, проверка черновика перед набором и `box_shows` после) видит только символы, без атрибутов, и принимает подсказку за черновик пользователя. Короткие команды проходили только когда подсказки не было.

Второй возможный отказ той же природы: команда длиннее ширины терминала переносится в поле ввода на вторую строку, а `box_shows` требует ровно одну строку.

Сделать:
1. Экран отдаёт вместе с текстом признак «приглушённый» (dim/faint SGR 2 или серый цвет, каким Claude Code рисует подсказку и плейсхолдер): Unix — из `vt100` ячеек в `term.rs`; Windows — из атрибутов `ReadConsoleOutputW`/того, что уже читает консоль. Какой именно стиль у подсказки, проверить пробой (скрытой, без окон на экране пользователя; Linux-проба в %TEMP% копии через pty, если на Windows нельзя) и записать в FINDINGS.
2. Приглушённый текст в поле ввода не считается черновиком ни до набора, ни после (набранный текст заменяет подсказку).
3. `box_shows` склеивает перенесённые строки поля ввода (продолжение строки без глифа промпта) перед сравнением.
4. Формат ответов экрана по unix-сокету (`term.rs` Ask/answer) меняется совместимо: старый `cctg run` без признака продолжает работать как сейчас.

- [ ] Команда, перенесённая на 2+ строки поля ввода, распознаётся (unit-тест)
