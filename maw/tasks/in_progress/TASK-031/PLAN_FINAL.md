## 1. Summary

В корне репозитория появляется один POSIX-скрипт `install.sh` (Linux, macOS, Windows в Git Bash; запуск `curl -fsSL https://raw.githubusercontent.com/pockerhead/cctg/<тег>/install.sh | sh -s -- ...` или из клона). Скрипт тега ставит бинарник того же тега: в нём строка `RELEASE=v0.1.0`, бинарник берётся из `releases/download/<тег>/cctg-<тег>-<триплет>[.exe]` (имена ассетов 035 не меняются), сверяется с `SHA256SUMS` того же релиза (несовпадение: ничего не ставится), кладётся в стабильный путь `~/.cctg/bin/cctg[.exe]` заменой на месте (в Windows работающий файл сначала переименовывается в `cctg.old.exe`). Скрипт пишет `~/.cctg/device.env` (секрет, адреса, pin; режим 600; одинарные кавычки, dotenvy читает их буквально), `~/.cctg/claude/{mcp.json,settings.json}` (агент, все хуки, статусная строка с абсолютным путём бинарника) и обёртку `~/.local/bin/claude-cctg` (+ `.cmd` в Windows) через `cctg run`; пользовательские `~/.claude/settings.json` и `~/.claude.json` не пишет никогда. Файл переписывается только при изменении байтов (иначе «Обновить» перезапускал бы claude). Секрет берётся из `CCTG_HUB_SECRET` (сразу `unset`), `--secret-file` или скрытого ввода с `/dev/tty`, никогда не печатается и не попадает в argv дочерних процессов. Вопросы идут только через `/dev/tty`; без терминала или с `--yes` вопросов нет, недостающее обязательное (секрет, pin удалённого hub) = понятная ошибка. Claude Code ставится официальным установщиком Anthropic по вопросу (или `--yes`). `--hub` поднимает hub на сервере через docker compose из файлов 035 (секрет, самоподписанный сертификат, `hub.env` 600, ожидание `hub started, polling`) и печатает строку установки клиента с тегом, адресом, pin и секретом. В бинарнике добавляются `cctg doctor` (проверка обоих каналов, pin и секрета) и маршрут hub `POST /v1/ping` (204 с секретом; те же ограничения до секрета, что у хуков). README по-русски для новичка, правки `docs/remote-hub.md`, `CLAUDE.md`, CI (shellcheck) и `release.yml` (тег обязан совпадать с `RELEASE=`).

### Шаг 1. Маршрут `POST /v1/ping` на hub

- `crates/cctg/src/wire.rs` после `HOOK_PATH`: `pub const PING_PATH: &str = "/v1/ping";` (doc: пустой POST, 204 с секретом, 401 без, 404 у hub старше). `VERSION` не меняется.
- `crates/cctg/src/hub/ingress.rs`: `PING_PATH` в импорт `crate::wire`; `enum Route` + `Ping`; разбор цели `PING_PATH => Route::Ping`; в `hook_request` ветка `Ok(Ok((Route::Ping, _))) => { debug!(%peer, "ping answered"); Status::NoContent }`. Секрет, `Content-Length`, дедлайн от accept (`REQUEST_TIMEOUT` 2 с), `MAX_HEAD` до секрета, `MAX_HOOK_REQUESTS` и пауза `AUTH_FAIL_DELAY` 250 мс перед 401 остаются общими для всех маршрутов (ветка стоит после `read_request`, 401 обрабатывается общим `if status == Status::Unauthorized`). Ping не новый оракул секрета: `POST /v1/hook` уже отвечал 401/204 с той же паузой.
- Тест `a_ping_checks_the_secret_and_is_no_event` в `ingress::tests`: 204 с секретом, 401 с чужим, `hook::ping` = `Ok`, событий нет.

### Шаг 2. `cctg doctor`

- `crates/cctg/src/hook.rs`: тело `post` выносится в приватный `exchange(addr, path, secret, body: &[u8], timeout) -> Result<u16, PostError>` (заголовки, `write_all`, `flush` из 035, строгий разбор статуса без изменений); `post` = `exchange(HOOK_PATH, ..)` + `204 => Ok`; новый `pub async fn ping(addr, secret, timeout)` = `exchange(PING_PATH, &[])`.

## 5. Review notes

Counter-example, проверенный первым: «секрет со всеми спецсимволами (`'`, `$`, `#`, `"`, `\`, `` ` ``) под dash (Ubuntu `/bin/sh`) записывается в `device.env` так, что настоящий `cctg` читает его не байт в байт». Проверено: исходник `dotenvy-0.15.7/src/parse.rs` (`'…'\''…'` = сильные кавычки + экранированная `'` вне кавычек, `$` внутри `'` не раскрывается) и прогон `install_e2e` с `dash.exe` из Git for Windows в роли `sh` (временная правка теста, откатана): все устройства-тесты зелёные, doctor «took the secret».
